## 现象

`dc-harness issue <target>` 的目标既可填注册表里的仓名，也可填仓的目录。提报方的会话因此可以、也常常直接写对方仓在本机的路径，路径随后出现在提报方的命令记录与文档里。

harness-workspace 现在的口径是：issue 只提给自己所依赖的供应方，按注册表仓名寻址，不在本仓文档与命令里写对方的路径。这条目前只是文字，工具不拦也不提示。

## 复现路径

1. `dc-harness issue ~/某仓目录 -t … -s … -b …` 能成功投递，无任何提示。
2. 同一目标若已在注册表登记，填仓名同样成功。

## 期望（供分诊参考）

目标是目录且该仓已在注册表登记时，提示改用仓名；是否直接拒绝由本仓定。
