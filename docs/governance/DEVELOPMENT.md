# 项目开发模式

> 文档定位：快照型 · 适用于本项目所有目录的开发任务，由项目根 AGENTS.md 要求读取。

## 领域与批次

- **领域划分**：一项能力的全部技术落点组成一个领域（清单见本目录 `MODULES.md`），领域是最小交付单位；其 cli、MCP 工具、skill、前端视图等落点一起交付，[MUST NOT] 按技术层拆任务。某 cli 日后补了新落点（如前端视图）⇒ 并入原领域。
- **批次单**：一张单含 N 个领域，一张单 = 一个会话 = 一次交付。单领域批次只是 N=1，[MUST NOT] 据此设置常驻「领域会话」。
- **批次串**：一个窗口串行做完的几批，每批任务表末项写「交付后立即开始下一批 `<id>`」，串末写收工。接到串首 id 就做到串末。

## 执行与进度

- 承接批次时，需求正文、所涉领域快照和契约是执行依据。能从这些材料与代码中核实、推导的细节 [MUST] 自行补齐。
- 进度 [MUST] 随手写进本批次 `PROGRESS.md`，让上下文压缩后的会话能从文件恢复。
- 只有不同理解会导致实质不同的实现，且读遍相关代码、快照、契约和 git 后仍判不定时，才就该处提问。

## 共享骨架与提交

- 触及共享骨架（`packages/cli` / 根 `package.json` / `pnpm-lock.yaml` / `pnpm-workspace.yaml` / `lerna.json` / `.github/workflows/`）[MUST] 在本批次 `PROGRESS.md` 写明独占，另一方排队。
- `pnpm-lock.yaml` 的处理按全局规则；本仓增量：所用 pnpm 版本 [MUST] 与 CI 一致（CI 构建后出现非 d.ts 脏文件即失败）。
- 提交用显式 pathspec：`git commit -F <msg> -- <路径>`；[MUST NOT] `-a` / `-am` / `git add -A`。提交骨架文件前 `git diff --cached -- <file>` 逐 hunk 确认。
- 提交单位 = 一个自包含可验证的完整变更；[MUST NOT] 提 WIP，[MUST NOT] 攒到整批末尾才提。

## 停止与交付条件

ⓐ **缺权限**：破坏性写、不可逆动作、push、发版或扩大对外暴露面，且缺少本次执行许可。授权在册不等于本次执行许可。
ⓑ **前提不成立**：需求前提已被证据否定，或与既有契约冲突；[MUST] 带证据报告。
ⓒ **缺资源**：缺少自行无法取得的凭据、环境或外部服务。
ⓓ **交付完成**：按本目录 `AGENTS.md`「收口」顺序完成——未完成条目已回池、所涉领域快照已更新、批次已归档、快照改动不晚于归档 commit、`pnpm gov:check` 退 0、所涉包门禁（eslint / 包内 test / build）退 0。

除以上情形外，[MUST] 持续推进当前已授权批次；[MUST NOT] 用半成品汇报或「是否继续」代替执行。
