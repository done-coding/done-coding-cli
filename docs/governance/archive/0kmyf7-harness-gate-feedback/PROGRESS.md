## 设计与理由

- **非破坏性**：不带前缀的 public、未开 `exportedNames` 的配置，判定与 0.5.0 一致；骨架行 public 照旧不校验模式。会多报的只有两类，都是本批要修的漏报：未 `git add` 的新文件（sab3rz），以及 Vue / Python 原先漏识别的引用（7m924q、cjf54l ⓐ）。cjf54l ⓑ 只会少报（字符串、注释里的 import 不再算）。
- **public 使用方**：用反引号内前缀（`骨架:` / `测试:`，另认英文 `skeleton:` / `test:`），不加新列。rhfv9v 的「装配入口」和 5pmb5g ⓓ 的「只对测试开放」是同一机制的两种取值；不是已知前缀的整串仍按路径模式处理。
- **`__all__` 规则只做 Python**：TS 没 `export` 的名字编译器本就不让 import，没有这类漏洞。没写 `__all__`、或 `__all__` 不是字面量列表时无从判定，不报。
- **pytest 基准目录**：测试模块所在目录向上第一个不含 `__init__.py` 的目录（pytest 缺省 prepend 模式）；只在常规解析找不到、且引用方本身是测试模块时启用。多个基准目录都有同名模块时取离引用方最近的，运行时实际取哪个取决于收集顺序。`pythonpath` ini 配置不读。
- **w6d0yv ⓑ**：原实现本就不要求已替换行去掉标注，同一文件出现在已替换行和等待行不冲突，冲突只在文档措辞；文档改为写明「一个文件可承载多个接缝」。新增的按标识对行只在标识只对上已替换行时报错，不带标识的标注不受影响。
- **i5t6hl**：治理目录各项按报错前缀归组（元闸 / 并行闸含批次串 / 收口形态 / 清单），认不出的单列「其他」。
